    18→PART A — THE COGNITIVE CORE (what the intelligence runs on)
    19→§A1 — Canonical Entity Graph + Knowledge Graph
    20→* Canonical models: Person(→Student/Guardian/Staff), Household, AcademicUnit(Class→Section→SubjectGroup), AcademicYear/Term, FeePlan, Route/Vehicle/Stop, Room/Asset, Document, Certificate, Policy (ALL school rules as versioned data: grading bands, fine rules, numbering, punch geofence/windows, proration, clearance gates — the AI reads policies as data, so changing a policy changes system behavior with zero code).
    21→* Relationships as first-class rows (guardian_of, sibling_of, authorized_pickup_of, emergency_contact_of, teaches, class_teacher_of, assigned_route) → the graph is queryable by agents: "all students of teacher X whose siblings have overdue fees" is one traversal, not a report request.
    22→* Deduplication service (fuzzy: name+DOB+phone+address embedding) on every person-create; merge UI preserving full history.
    23→* Document & Certificate Vault (single typed store): every uploaded document (birth certificates, ID proofs, previous TCs, mark sheets, medical, category certificates, photos; staff resumes, qualifications, contracts, police verification) and every generated artifact (report cards/scorecards across all years, hall tickets, TCs, bonafide/character certificates, ID cards, receipts, payslips): documents(id, entity_refs[], doc_type, issued_by, issue/expiry dates, sensitivity_tag, storage_key_encrypted, ocr_text_indexed, version, status[verified|pending|rejected]). Verification workflow, expiry engine (30/7/1-day alerts), role-scoped visibility per §C matrix.
    24→* ProfileCompleteness + DataFreshness per entity → missing critical fields auto-generate chase sequences.
    25→§A2 — Event Backbone (the sensory system)
    26→* events(id ULID, school_id, type, entity_refs, payload, actor{human|ai|system,id}, causation_id, correlation_id, occurred_at) — causation chains power one-click "why did this happen" explainability.
    27→* Transactional outbox (domain write + event in one transaction; relay → BullMQ/Redis or DB queue). Zero lost events. Idempotent consumers, retry+backoff, DLQ→human task. Silent failure forbidden.
    28→* ~80 typed events across lifecycle/academic/financial/operational/safety/engagement, including staff.punched_in/out/punch_missing/late_arrival and meta-events (rule.fired, plan.prepared/confirmed/rejected, prediction.issued, simulation.completed) — the system's own actions are events, so the AI can reason about its own behavior.
    29→§A3 — Workflow, Rules & the Two-Phase Action Protocol
    30→* Saga orchestrator: versioned JSON workflow definitions (steps, compensations, human-gates, timeouts), crash-safe resumable instances.
    31→* Rules engine: automation_rules(school_id, trigger, conditions AST, actions[], tier, enabled, version) + default pack + simulation mode (shadow-run, log intended actions, execute nothing).
    32→* Two-phase protocol for every AI mutation: prepare → ActionPlan (human-readable summary, exact record diffs, affected-person count, tier, 15-min expiry) → confirm → execute through the SAME service layer and permission middleware as manual operations → post-condition verify → event log (actor:ai, approved_by). Stale underlying data invalidates plans. The AI is a client of the API — never a backdoor.
    33→§A4 — The Agent Mesh (specialists, orchestrated)
    34→AIFabric service hosting a registry of agents, each with: system prompt, tool allowlist, data-scope, output schema, autonomy tier:
    35→* IntakeAgent — photo/PDF/voice/CSV/chat → structured data; per-field confidence; <0.85 → human review; handles paper registers, admission documents, mark sheets, invoices, resumes, voice-logged phone calls.
    36→* OpsAgent — substitution plans, seating plans, invigilation rosters, timetable drafts (OR-Tools/CSP solver computes; LLM translates natural-language constraints into solver parameters and explains results in plain language).
    37→* FinanceAgent — dunning sequences, reconciliation triage, fee-risk scoring, concession policy checks, payroll variance explanations.
    38→* CommsAgent — every outbound message: guardian's language, preferred channel, school's voice profile (learned from approved messages); sensitive categories always human-gated.
    39→* SentinelAgent (new) — watches the system itself: queue lag, DLQ growth, integration failures, webhook silence, extraction-accuracy drift, cost spikes → auto-remediates known failures (retry, failover channel, model fallback) and files IT tasks for the rest. The platform self-heals.
    40→* InsightAgent — pattern detection over the event stream: attendance decay, marks anomalies (entry error vs real decline, judged against history), workload imbalance, at-risk composite scores (attendance × grade-trend × incidents × engagement — factors stored, explainable).
    41→* BriefingAgent — role-scoped daily briefings + natural-language analytics with one-click bulk actions.
    42→* CopilotAgent — the per-role conversational interface (Part C): routes intents to specialist agents, executes registered actions via two-phase protocol, holds per-user memory.
    43→* Orchestration: agents call agents through the registry with scope inheritance (a chain can never exceed the initiating human's permissions — enforce and test).
    44→§A5 — Model Router & Continuous Evaluation (industrial-grade AI, not a demo)
    45→* Model router: task-class → model tier (fast/cheap for extraction/classification/routing; powerful for drafting/reasoning/planning), with automatic fallback chains, structured-output enforcement (JSON-schema validation + one repair retry), timeout budgets. Model choice is config, never hardcoded.
    46→* Evaluation harness (mandatory): golden datasets per AI task (extraction fixtures: admission forms, registers, mark sheets in real-world quality; drafting rubrics; injection attack corpus). Runs in CI — an agent change that drops extraction accuracy below threshold fails the build.
    47→* Learning loops without retraining: track approved-vs-edited deltas on every AI draft (remarks, messages, plans). Weekly job clusters edits → proposes prompt/few-shot refinements per school → applied behind flags with A/B measurement. The AI measurably improves at each school's style over time.
    48→* Full telemetry: agent_invocations(agent, model, tokens, latency, cost, purpose, outcome[approved|edited|rejected]) → cost/quality dashboards per school for Super Admin and per-feature ROI.

    51→PART B — THE AUTONOMY STACK (what makes it self-driving)
    52→§B1 — School Day Autopilot (ambient, time-aware orchestration)
    53→A per-school orchestrator that knows the daily rhythm (from timetable + policy + calendar) and runs scheduled checkpoint loops — the school's heartbeat:
    54→* 06:00 — BriefingAgent compiles role briefings; transport manifests built from yesterday's exits/entries + leave records; weather/holiday calendar check (unplanned closure → mass-notification workflow prepared for Head, Tier B).
    55→* First-bell − 45 min — punch-in sweep: expected vs punched staff → gaps get auto-prompts → unanswered by cutoff → OpsAgent prepares substitution plans BEFORE any class is disrupted; coordinator sees a ready plan, not a problem.
    56→* Period 1 + 15 min — attendance sweep: unmarked sections get teacher nudges (Focus-SIS-style, but automatic); marked absences already flowing to parents (<30s each); transport no-shows reconciled against absence records → mismatches (on bus but marked absent, or vice versa) → instant safety alert.
    57→* Mid-day — fee payments reconciled live (gateway webhooks); clinic visits notified; homework due-today reminders.
    58→* Last bell — gate/dispersal mode: authorized-pickup verification active, transport boarding reconciliation, hostel roll sync.
    59→* 18:00 — day-close digest per role; incomplete registers escalated; tomorrow's substitution risks pre-computed from approved leaves.
    60→* Night — InsightAgent full-stream scan, at-risk score refresh, prediction jobs (§B3), index maintenance, SentinelAgent deep health pass, backup verification. Every checkpoint is a configurable workflow (policy-as-data), visible in an Autopilot console for the Head: what ran, what it found, what it did, what awaits a human.
    61→§B2 — Automation Discovery Engine (the system that automates itself)
    62→The signature capability no competitor has:
    63→* Mine the event log for repeated human action patterns: same actor/role performing the same action sequence in response to the same trigger conditions N times (e.g., Administrator manually messages parents every time a library book passes 14 days overdue).
    64→* Cluster → synthesize a candidate automation_rule → present in plain language: "You've done this 14 times this term. Shall I automate it? [Simulate 7 days] [Enable Tier B] [Dismiss]".
    65→* Accepted candidates default to simulation mode first; promotion to live requires the role that owns the pattern (or Head, per tier).
    66→* Track adoption: rules born from discovery vs shipped defaults — the system's autonomy measurably grows per school. Show the Head an "automation coverage" score trending up.
    67→§B3 — Predictive & Prescriptive Layer (see around corners)
    68→Nightly + on-demand prediction jobs; every prediction stored versioned with factors (explainable), every prediction paired with a prescriptive one-click action:
    69→* Student at-risk / dropout risk — attendance trajectory × grade trend × fee stress × engagement × incidents → counselling referral plan prepared.
    70→* Fee default risk per household — payment history, sibling patterns, partial-payment signals → pre-term proactive plans (installment offer draft, early gentle reminders) instead of post-due chasing.
    71→* Enrollment forecasting — admissions funnel velocity + historical seasonality → section-planning suggestions (open a new 4th section of Grade 1?) for Head.
    72→* Collection forecasting — expected cash inflow per month vs payroll/expense obligations → early warning on gaps.
    73→* Staff attrition & burnout signals — punch patterns, leave patterns, substitution load imbalance, appraisal deltas → workload rebalancing proposals.
    74→* Resource utilization — room/lab/bus occupancy patterns → optimization proposals. Start with transparent statistical/gradient-boosted baselines on event-log features (not LLM guessing); LLM explains predictions in plain language. Accuracy tracked per school; predictions below reliability threshold auto-hide (never show numbers you can't stand behind).
    75→§B4 — Digital Twin: What-If Simulator
    76→Before a school changes anything consequential, it can simulate against its own historical data:
    77→* Fee structure change → projected collection impact, affected-household distribution, default-risk shift.
    78→* Timetable policy change (period length, start time) → teacher load distribution, room conflicts.
    79→* New admission batch → transport capacity, section balance, staffing needs.
    80→* Automation rule change → replay last 90 days of events through the new rule: exactly what WOULD have fired. Output: side-by-side current-vs-simulated with confidence notes. This turns the ERP into a decision instrument, not a record keeper.
    81→§B5 — Natural-Language & Voice Command Surface (the interface dissolves)

   121→AI acts only through the same service layer + permission middleware as humans; zero AI-only mutation paths; agent chains inherit (never exceed) the initiating human's scope.    123→Tier A auto+log: receipts, routine notifications, ledger math, manifests, expiry alerts, index updates, autopilot sweeps.
